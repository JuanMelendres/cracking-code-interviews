CAPTURE NOTE (read this first)
==========================================================================
This is real, captured `curl -v` output against a real running Python
http.server process serving this directory's index.html/styles.css/app.js.

The one deviation from the plain "python3 -m http.server 8000" + "curl -v
http://127.0.0.1:8000/" recipe: the sandbox this was captured in blocks TCP
connections to 127.0.0.1/localhost outright (confirmed by direct socket
tests — the listening process is alive and visible in `ps`, but no TCP
client, including a plain Python socket.connect(), can reach it). Unix
domain sockets are NOT blocked, so the server below is a two-line subclass
of http.server.HTTPServer with address_family = socket.AF_UNIX, and curl
talks HTTP to it over that socket via `--unix-socket`. The request line,
headers, status codes, and bodies below are exactly what a real HTTP/1.0
exchange with Python's http.server produces — nothing here is invented.
On a normal machine (a laptop, a CI runner without this restriction), the
identical server code, run as plain `python3 -m http.server 8000` and
queried with `curl -v http://127.0.0.1:8000/`, produces the same headers
over an ordinary TCP socket. See README.md for both the exact commands
used here and the standard TCP-based reproduction steps.
