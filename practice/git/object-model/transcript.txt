will be IDENTICAL on any run, anywhere -- that is the entire point of
content-addressable storage. Commit hashes include a timestamp and therefore
differ run-to-run; the ones below are from one real execution, kept verbatim
rather than redacted.

Note: file-copy.txt and file.txt are two different FILENAMES pointing to the
exact same blob object (3b18e512...) in the tree listing above -- git never
stores the same content twice, regardless of how many files or commits
reference it. This is the mechanism that makes git repos with many similar
file revisions (e.g. large refactors, renamed files with unchanged content)
storage-efficient: renames and duplicate content cost effectively nothing in
the object store, only a new tree entry.
