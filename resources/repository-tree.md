**Regeneration method changed 2026-09-13.** The prior method (`find . \( -name .git -o ... \) -prune -o -print`) required manually maintaining an exclude list, and that list silently drifted out of date: it never accounted for `.venv-docs/` (a distinct directory from the already-excluded `.venv/`, added for this repository's MkDocs site tooling) or `site/`/`docs/*` (MkDocs build output, mostly gitignored) — by the time this was caught, those three directories alone inflated a fresh `find` run to over 33,000 lines, more than 10x the real, authored content. `git ls-files` lists exactly the repository's tracked content by definition, with no exclude list to maintain or let drift — gitignored build artifacts, dependency installs, and caches are automatically absent regardless of what gets added to the project later. This does mean directory entries themselves (e.g. a bare `./study-packs` line) no longer appear, only files — `git ls-files` doesn't track empty or directory-only paths, which is a real, accepted trade-off for a method that can't drift the way the manual exclude list did.
