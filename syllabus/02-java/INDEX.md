> **Gap found and closed: PriorityQueue Internals (2026-09-10).** A full repository-wide 22-domain gap audit found `02-java/collections` had zero dedicated coverage of `PriorityQueue` despite every other core collection (`HashMap`, `ArrayList`/`LinkedList`, `TreeMap`/`TreeSet`, `ArrayDeque`, `ConcurrentHashMap`, `CopyOnWriteArrayList`, `BlockingQueue`) already having its own T-2xx chapter — a real, high-frequency gap, since `PriorityQueue` is the standard tool for Dijkstra's algorithm and top-K problems. Closed with [PriorityQueue Internals](collections/priorityqueue-internals.md) (T-210), backed by a real demo (`practice/java/collections/priorityqueue-internals/`) proving the real binary-heap ordering guarantee (`poll()` only, never iteration), a real, measured comparison-count proof of O(log n) `poll()` (not asserted from documentation), and a real `ConcurrentModificationException` confirming `PriorityQueue` is fail-fast like its siblings.
>
> **Gap found and closed: java.time API (2026-09-10, same audit).** `02-java/language-core` had zero coverage of `java.time` (JSR-310) despite it being explicitly named in `CLAUDE.md`'s own Java Core gap list and being Very High interview frequency. Closed with [java.time API: Dates, Times, and Durations](language-core/java-time-api.md) (T-2400), backed by a real demo (`practice/java/language-core/java-time-api/`) proving real immutability against a real `Calendar` in-place-mutation contrast, a real `Period`-versus-`Duration` divergence on an actual US DST transition date (landing at genuinely different wall-clock hours from the identical starting point), and — the marquee finding — a real, reproduced `SimpleDateFormat` thread-safety corruption under concurrent load (6,969 of 10,000 calls corrupted in one captured run against a shared instance), versus zero corruption for the identical workload against a shared `DateTimeFormatter`.
>

Closed with [java.util.concurrent Synchronizers](concurrency/synchronizers-countdownlatch-cyclicbarrier-semaphore.md) (T-417), backed by a real demo (`practice/java/concurrency/synchronizers/`) proving real `CountDownLatch` blocking-until-all-signal behavior with staggered real worker delays, real evidence it cannot be reset for a second round, a real `CyclicBarrier` reused across two independent rounds (its barrier action firing exactly twice on the same instance), and a real, measured `Semaphore` maximum-concurrent-holder count (never exceeding the configured permit count under genuine contention from more threads than permits).
