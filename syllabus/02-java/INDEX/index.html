    Phase 3 update (2026-09-03). This domain's full existing content has physically relocated via git mv from handbook/{java-core,collections,jvm,concurrency}/, preserving file history. 235 files across the rest of the repository (cheat-sheets/, flashcards/, production-cookbook/, other handbook/ chapters, study-packs/, architecture-atlas/, practice/) had their cross-references to these 49 chapters updated to the new paths; a full repository-wide link-resolution pass confirms zero references broken by this move.     Phase 5 update (2026-09-04) — domain complete. All four subdomains — collections (T-201–T-209, 9 chapters), language-core (T-101–T-115, 15 chapters), jvm-internals (12 chapters), and concurrency (13 chapters) — have now received the plan's own additive L1/L2 retrofit (§2.4): every chapter gained a new "Level 1 — Foundation" and "Level 2 — Working Knowledge" section, inserted between the existing "Why This Matters in Interviews" and "Mental Model" sections, per the plan's own stated placement. No existing sentence was deleted, reworded, or moved anywhere across all 49 chapters — every retrofit was a pure insertion, verified by diff, file by file. Each chapter also gained a mastery_levels_covered: [L1, L2, L3, L4] front-matter field, and a topic_id field where one already exists in the Master Topic Register (5 jvm-internals chapters have none, and were left without a fabricated one). 02-java is the first fully L1–L4 domain in the syllabus.

    Junior Fundamentals gap found and started (2026-09-07). The L1/L2 retrofit above added intuition for existing Senior-level topics — it never added a true zero-to-one entry point, because this domain's original Target Audience (per CLAUDE.md) assumed 5+ years of Java experience already. An audit triggered by the user (checking whether OOP itself was covered before selling this repository as Junior-through-Staff) found it was covered only narrowly — T-102, Polymorphism and Dynamic Dispatch Mechanics, by original design, scopes "OOP" down to the one Senior-differentiating mechanic, not the four pillars — and the same narrow-assumption pattern repeats across 05-spring, 06-databases, 07-api-design, and 08-testing. The user chose the full-scope fix: one true "101" chapter per affected domain, using a newly reserved ID range (T-2200–T-2299, see 00-project/syllabus-transformation-plan.md). Java OOP Fundamentals: Classes, Objects, and Interfaces (T-2201) is the first of five, with 3 real, compiled, executed demos (19/19 assertions passing on OpenJDK 21.0.12) proving encapsulation, the interface-vs-abstract-class distinction, and composition-over-inheritance directly rather than asserting them. Update: all five chapters (T-2201–T-2205) are now written — see syllabus/07-api-design/INDEX.md's matching note for the closing entry. Cheat sheet and flashcard deck for T-2201 added 2026-09-07 (cheat-sheets/README.md, flashcards/README.md).

    Two further gaps found and closed (2026-09-08). After completing the Junior Fundamentals initiative, the user asked directly whether the repository now genuinely served a low-to-high-seniority reader. Honest answer: not entirely — T-2201 itself assumed the reader could already read an if statement and a for loop (true programming-syntax literacy was never taught anywhere in this repository), and the domain jumped from "here's a class" straight to HashMap/ArrayList internals with no "what is a List/Map/Set and when do you use each" usage-level stop in between. Closed both: Java Syntax Fundamentals: Variables, Control Flow, and Methods (T-2206) is now the true first stop (T-2201's own prerequisites: updated to point to it), and Collections Usage Fundamentals: List, Map, and Set (T-2207) sits between OOP Fundamentals and this domain's internals-focused collections chapters. Both ship with real, compiled, executed demos (9/9 and 14/14 assertions passing respectively, OpenJDK 21.0.12) — 02-java now has 52 chapters.

    Three more gaps found and closed (2026-09-08, same day). The user asked explicitly whether this domain covered primitive types, JVM/JDK/JRE, basic data structures, access modifiers, static/final/finalize, abstract-vs-concrete method signatures, and a Java-version feature timeline (8/11/17/21/25) — and to check a connected Notion knowledge base for real, commonly-asked questions on these exact topics. Investigation found: basic data structures were already covered by T-2207; the diamond problem and default/static interface methods were already covered by T-2201 §4/§8; but JVM/JDK/JRE, the full primitive-type table, access modifiers, static/final/finalize, and abstract-vs-concrete method signatures had zero dedicated coverage anywhere in this domain, and no chapter gave a single accurate timeline of Java version features. The connected Notion workspace (searched read-only, per CLAUDE.md's Notion safety rules — nothing was written or modified) confirmed these are real, commonly-asked questions there too, though its own answers are shallow one-paragraph Q&A entries, not copied. Closed with three new chapters: Java Platform Basics: JVM, JDK, JRE, and Primitive Types (T-2209, now the true Topic 1 in Junior → Mid), Java Modifiers and Method Signatures (T-2210), and Java Version Features Timeline: Java 8 Through 25 (T-2211, cross-linking to existing Java-8-feature chapters rather than duplicating them). All three ship with real, compiled, executed demos (11/11, 6/6 plus 5 real captured compiler errors, and 9/9 assertions respectively, OpenJDK 21.0.12) — including a genuine, unplanned finding discovered while building T-2210's demo (that private access is scoped to the top-level enclosing class, not the immediate class body). 02-java now has 55 chapters.

    Gap found and closed: PriorityQueue Internals (2026-09-10). A full repository-wide 22-domain gap audit found 02-java/collections had zero dedicated coverage of PriorityQueue despite every other core collection (HashMap, ArrayList/LinkedList, TreeMap/TreeSet, ArrayDeque, ConcurrentHashMap, CopyOnWriteArrayList, BlockingQueue) already having its own T-2xx chapter — a real, high-frequency gap, since PriorityQueue is the standard tool for Dijkstra's algorithm and top-K problems. Closed with PriorityQueue Internals (T-210), backed by a real demo (practice/java/collections/priorityqueue-internals/) proving the real binary-heap ordering guarantee (poll() only, never iteration), a real, measured comparison-count proof of O(log n) poll() (not asserted from documentation), and a real ConcurrentModificationException confirming PriorityQueue is fail-fast like its siblings.

    Gap found and closed: java.time API (2026-09-10, same audit). 02-java/language-core had zero coverage of java.time (JSR-310) despite it being explicitly named in CLAUDE.md's own Java Core gap list and being Very High interview frequency. Closed with java.time API: Dates, Times, and Durations (T-2400), backed by a real demo (practice/java/language-core/java-time-api/) proving real immutability against a real Calendar in-place-mutation contrast, a real Period-versus-Duration divergence on an actual US DST transition date (landing at genuinely different wall-clock hours from the identical starting point), and — the marquee finding — a real, reproduced SimpleDateFormat thread-safety corruption under concurrent load (6,969 of 10,000 calls corrupted in one captured run against a shared instance), versus zero corruption for the identical workload against a shared DateTimeFormatter.

    Gap found and closed: java.util.concurrent Synchronizers (2026-09-10, same audit). 02-java/concurrency had zero coverage of CountDownLatch, CyclicBarrier, or Semaphore despite them being explicitly named in CLAUDE.md's own Concurrency gap list and being a standard, High-frequency interview topic distinct from the locks and atomics this domain already covers deeply. Closed with java.util.concurrent Synchronizers (T-417), backed by a real demo (practice/java/concurrency/synchronizers/) proving real CountDownLatch blocking-until-all-signal behavior with staggered real worker delays, real evidence it cannot be reset for a second round, a real CyclicBarrier reused across two independent rounds (its barrier action firing exactly twice on the same instance), and a real, measured Semaphore maximum-concurrent-holder count (never exceeding the configured permit count under genuine contention from more threads than permits).

    Gap found and closed: Java Platform Module System (2026-09-10, same audit). 02-java had zero coverage of JPMS despite it being explicitly named in CLAUDE.md's own Java Core gap list. Unlike this audit's other 02-java gaps, this one had a real, pre-existing, correctly-reserved slot in the original Master Topic Register (T-116, "Java Platform Module System," EXP tier, IWI 3.2, Rare frequency, 🔴 absent) — never written, and briefly, mistakenly, misassigned to a different topic (java.time API) earlier the same day before that collision was caught and fixed (see 00-project/syllabus-transformation-plan.md's Topic-ID collision note). Closed with Java Platform Module System (JPMS) (T-116), backed by a real demo (practice/java/language-core/jpms-module-system/) proving exports and opens are genuinely independent grants (a real InaccessibleObjectException under exports-only, fixed by adding a qualified opens), and that ServiceLoader's uses/provides mechanism resolves a provider module the consumer never requires — while a direct import of that same provider's internal package still fails to compile with a real javac error, proving the SPI exception is narrowly scoped, not a general encapsulation hole.

    Gap found and closed: MethodHandle and java.lang.invoke (2026-09-10, same audit). 02-java had no dedicated coverage of MethodHandle — Reflection and Dynamic Proxies (T-113) used it only as a performance comparison point, never as its own topic, despite MethodHandle being explicitly named in CLAUDE.md's own Java Core gap list and being the real mechanism behind lambda expressions. Closed with MethodHandle and java.lang.invoke (T-2405, a genuinely new topic — the original Master Topic Register never had a dedicated entry for it), backed by a real demo (practice/java/concurrency/methodhandle-and-invoke/) proving invoke() vs. invokeExact()'s real behavioral difference (a real WrongMethodTypeException), real bindTo/combinator (filterReturnValue, dropArguments) mechanics, and — the marquee finding — a real javap -v disassembly showing a compiled lambda's invokedynamic instruction and its LambdaMetafactory.metafactory bootstrap method, contrasted directly against a real, extra .class file the equivalent anonymous inner class produces at compile time.

    Gap found and closed: Bytecode and Class File Fundamentals (2026-09-10, same audit) — the third and last of CLAUDE.md's three named 02-java gaps, all now closed. 02-java had no dedicated coverage of the .class file format or the JVM's bytecode instruction set. Closed with Bytecode and Class File Fundamentals (T-2406, a genuinely new topic — absent from the original Master Topic Register entirely), backed by a real demo (practice/java/jvm/bytecode-and-class-file-fundamentals/) proving the real magic number and version bytes via a hex dump, a full real javap -v disassembly of a compiled loop (constant pool, real bytecode instructions, a real StackMapTable), and — the marquee finding — two real JVM failures each reproduced by patching exactly one byte on an otherwise-valid class file: a real UnsupportedClassVersionError from patching the major-version bytes, and a real VerifyError from patching a single opcode (iadd → iaload), each independently proving one of the JVM's two real, separate safety checks (version gating, then type-aware bytecode verification).
