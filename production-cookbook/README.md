# Production Cookbook

The Production Cookbook owns incident-oriented and troubleshooting content per `CLAUDE.md`'s Production Cookbook Standard: context, symptoms, impact, hypotheses, evidence, investigation timeline, root cause, immediate mitigation, permanent fix, alternatives, trade-offs, prevention, monitoring, an interview-story framing, and a Staff-level discussion — each entry referencing its canonical `handbook/` chapter rather than restating it.

## A note on scope and sourcing

Every entry here is elevated from an existing `## Production Scenarios` section already present in a canonical `handbook/` chapter — each of those chapters was written with a symptoms/evidence/diagnosis/mitigation scenario already worked out and grounded in the chapter's own measured demos. This deliverable does not invent new incidents; it takes each scenario's real content and expands it into the Cookbook's full incident-report template (investigation timeline, monitoring and alerts, interview story, Staff-level discussion), staying honest about which fields are direct extensions of the source material and which are new synthesis grounded in it. Per `CLAUDE.md`, no personal experience is fabricated — the Interview Story section in every entry is explicitly framed as a representative scenario to adapt, not a claimed personal history.

This deliverable was declared **complete** on 2026-08-05 at 70 entries across eighteen batches, spanning all 13 handbook domains, with the stated condition that a new entry would only be added if a future `handbook/` chapter is written with its own new production scenario. That condition has since fired: sixteen new `handbook/` chapters were added between 2026-08-05 and 2026-09-01, and fifteen of them carry a genuine `## Production Scenarios` section that had never been elevated here. This batch closes that gap, bringing the total to **85 entries**. The sixteenth chapter, `handbook/concurrency/foreign-function-and-memory-api.md`, is deliberately excluded — it was built as a shortened, Expert-tier/recognition-level chapter that omits a `## Production Scenarios` section along with several other template sections, so its absence here reflects that deliberate scope decision, not an oversight. No further batches are planned; a new entry would only be added if a future `handbook/` chapter is written with its own new production scenario.

**136 entries (2026-09-02).** The "no further batches" claim above was corrected once (flagging a 46-chapter gap) and is now closed: the same 46 chapters found missing while auditing `cheat-sheets/` — java-core, collections, concurrency, spring, databases, kafka, system-design, architecture, cloud, performance — have each been elevated. This produced **51 entries, not 46**, because 5 of the 46 chapters' `## Production Scenarios` sections contained two genuinely distinct `### Scenario:` incidents rather than one (`locks-deadlocks-and-lock-escalation.md`, `schema-registry-and-compatibility-evolution.md`, `load-balancing-service-discovery-and-health-checking.md`, `multi-region-failover-and-disaster-recovery.md`, `modular-monolith-as-a-deliberate-choice.md`) — verified per-chapter before writing, not assumed to be 1:1 from the prior batch's pattern.

Built via two parallel, independently-scoped background-agent batches (23 chapters each), mirroring `production-cookbook/broken-equals-hashcode-contract-letting-duplicates-through.md`'s exact template. Two chapters needed a shape judgment call rather than a straightforward runtime-incident elevation: `architecture-decision-records.md`'s scenario showcases three worked ADRs citing real, checkable evidence rather than a technical outage, elevated faithfully as a documentation-practice entry rather than forced into an incident narrative it doesn't have; `git-internals-and-collaboration-workflows.md`'s force-push scenario is genuinely incident-shaped (symptoms, diagnosis, prevention already present in the source) and was elevated normally.

**No invented incidents**, per the same discipline established in every prior batch: every entry's Context/Symptoms/Impact/Initial Hypotheses/Evidence/Root Cause/Immediate Mitigation/Permanent Fix/Trade-offs/Prevention was built by expanding that chapter's own `## Production Scenarios` text — new synthesis was limited to Investigation Timeline step-ordering, the Monitoring and Alerts section, and a fleshed-out Staff-Level Discussion, all grounded in the source scenario's own content. Verified before merging: all 51 files' YAML parses; every `source` path resolves to a real chapter; the two split-scenario chapters (`locks-deadlocks-and-lock-escalation.md`, spot-checked) were confirmed to genuinely contain two separate `### Scenario:` headings, not an artificial split. No further batches are planned; a new entry would only be added if a future `handbook/` chapter is written with its own new production scenario.
