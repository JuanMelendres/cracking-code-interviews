# Week 6 Mock — Technical + Coding

**Format:** 60-min technical, 45-min coding. Partner strongly preferred. This mock deliberately draws across all five prior weeks rather than one week's material — that's the entire point of a consolidation mock.

## Part A — Candidate script

**Technical (60 min) — one question drawn from each week, full nine-layer treatment where the interviewer pushes:**

1. Week 1: "Would you use hexagonal architecture on every project?"
2. Week 2: "Explain write skew with a concrete example." *(this is deliberately repeated from Week 3's own checkpoint — if it's still shaky here, that's exactly what this mock exists to surface)*
3. Week 3: "Method A calls a `@Transactional` method B in the same class. What happens, and what are your fixes?"
4. Week 4: "You added retries and made the outage worse. Explain the mechanism precisely."
5. Week 5: "Make a payment endpoint idempotent. Full mechanism."

**Coding (45 min) — interviewer's choice of one unseen-to-you problem from the pattern families covered across Weeks 1–5** (two pointers/hashing, binary search, stacks, trees, graphs, or design coding). Narrate all six phases from `study-packs/week-01/04-coding-interview-communication.md`.

## Part B — Interviewer script

1. For each technical question, push at least 3 follow-ups from that week's chapter before moving on — this mock should feel harder than any single week's mock, because it is.
2. On the write-skew question specifically: if the candidate's answer is noticeably weaker than it was in Week 3's checkpoint, flag this explicitly — that's a genuine regression signal the retrieval pass this week is designed to catch.
3. For the coding round, pick a problem the candidate has NOT already solved this program if possible, to test pattern transfer rather than memorized recall.
4. Score using `study-packs/week-01/10-week-1-evaluation-rubric.md`'s Technical Depth, Coding, and Java Fluency dimensions, then also score against `07-interview-readiness-rubric.md`'s targets specifically.
