## 1. Why this exists

A correct solution delivered in silence scores lower than a correct solution narrated, because the interviewer is evaluating a process they can only see if you describe it. Full reasoning: canonical chapter [§ Why This Exists](../../syllabus/20-interview-preparation/coding/coding-interview-communication-protocol.md#why-this-exists).

## 2. The six-phase protocol

Six phases, run in order on every problem: Clarify, State the invariant, Complexity upfront, Narrate while coding, Test before declaring done, Re-state complexity against the actual code. Full table with what to say at each phase: canonical chapter [§ The Six-Phase Protocol](../../syllabus/20-interview-preparation/coding/coding-interview-communication-protocol.md#the-six-phase-protocol).

## 3. Illustrative failure patterns

Three illustrative patterns — skipping clarify, skipping state-the-invariant, skipping test-before-done — each showing why that specific phase matters, elevated to the canonical chapter rather than duplicated here: canonical chapter [§ Illustrative Failure Patterns](../../syllabus/20-interview-preparation/coding/coding-interview-communication-protocol.md#illustrative-failure-patterns).
